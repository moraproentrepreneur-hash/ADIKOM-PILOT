\# ADIKOM PILOT

\## Objectifs du système



\*\*Version :\*\* 1.0  

\*\*Statut :\*\* Document de référence  

\*\*Entreprise :\*\* ADIKOM Technology \& Travel  

\*\*Projet :\*\* ADIKOM PILOT



\---



\## 1. Objectif général



L'objectif principal d'ADIKOM PILOT est de fournir à ADIKOM Technology \& Travel un système interne unique permettant de gérer, suivre et piloter progressivement ses activités.



Le système doit centraliser les informations essentielles de l'entreprise, structurer les processus de travail, clarifier les responsabilités et fournir à la Direction une visibilité fiable sur les opérations.



ADIKOM PILOT doit permettre de passer progressivement d'une gestion dispersée à une gestion structurée, traçable et pilotable.



\---



\## 2. Objectifs stratégiques



ADIKOM PILOT poursuit les objectifs stratégiques suivants :



\### 2.1. Structurer l'organisation interne



Mettre en place un système cohérent entre :



\- l'organigramme ;

\- les postes ;

\- les utilisateurs ;

\- les groupes ;

\- les responsabilités ;

\- les permissions ;

\- les processus.



Le logiciel doit refléter l'organisation réelle d'ADIKOM tout en restant suffisamment flexible pour accompagner son évolution.



\---



\### 2.2. Centraliser les informations



Réunir dans un même système les informations nécessaires au fonctionnement quotidien d'ADIKOM.



Cela concerne notamment :



\- clients ;

\- fournisseurs ;

\- partenaires ;

\- véhicules ;

\- réservations ;

\- contrats ;

\- factures ;

\- paiements ;

\- banques ;

\- caisses ;

\- projets ;

\- tâches ;

\- documents ;

\- utilisateurs ;

\- historiques.



L'objectif est de limiter la dispersion des informations et les doubles saisies inutiles.



\---



\### 2.3. Améliorer le suivi des opérations



Permettre aux utilisateurs de suivre les opérations depuis leur création jusqu'à leur clôture.



Chaque processus important doit pouvoir être suivi à travers ses différentes étapes.



Le système doit permettre d'identifier clairement :



\- ce qui a été créé ;

\- ce qui est en cours ;

\- ce qui est terminé ;

\- ce qui est en attente ;

\- ce qui est en retard ;

\- ce qui nécessite une intervention.



\---



\### 2.4. Améliorer le pilotage de la Direction



Fournir au Gérant une vision claire et synthétique de l'activité.



Le système doit permettre d'accéder rapidement aux informations importantes concernant :



\- l'activité de location ;

\- le parc automobile ;

\- les revenus ;

\- les paiements ;

\- les dépenses ;

\- les créances ;

\- les fournisseurs ;

\- les échéances ;

\- les tâches ;

\- les alertes ;

\- les performances.



L'objectif n'est pas seulement de présenter des chiffres, mais de permettre à la Direction de comprendre la situation et d'agir.



\---



\## 3. Objectifs opérationnels



\### 3.1. Digitaliser la gestion de location



La première priorité opérationnelle est de digitaliser le cycle complet de location de véhicules.



Le système doit permettre de gérer :



\- le parc automobile ;

\- les véhicules ;

\- les disponibilités ;

\- les tarifs ;

\- les clients ;

\- les réservations ;

\- les contrats ;

\- les départs ;

\- les retours ;

\- les états des lieux ;

\- les dommages ;

\- le kilométrage ;

\- le carburant ;

\- la maintenance ;

\- les assurances ;

\- les documents ;

\- les dépenses ;

\- la facturation ;

\- les paiements.



\---



\### 3.2. Réduire les erreurs opérationnelles



Le système doit réduire les erreurs liées à :



\- la double réservation d'un véhicule ;

\- la saisie manuelle répétitive ;

\- l'oubli d'une échéance ;

\- l'application d'un mauvais tarif ;

\- l'absence de suivi d'une maintenance ;

\- l'oubli d'un paiement ;

\- l'absence de justificatif ;

\- la perte d'informations.



Lorsque cela est possible, le système doit contrôler automatiquement les situations à risque et avertir l'utilisateur.



\---



\### 3.3. Gérer les tarifs préférentiels



Permettre à ADIKOM d'attribuer à certains clients des conditions tarifaires particulières.



Le système doit pouvoir :



\- enregistrer le tarif préférentiel d'un client ;

\- définir les conditions applicables ;

\- définir une période de validité ;

\- associer le tarif à un véhicule, une catégorie ou un service selon le besoin ;

\- proposer automatiquement le tarif applicable lors d'une réservation ;

\- conserver le tarif réellement appliqué à chaque réservation.



Les modifications futures d'un tarif client ne doivent pas modifier les anciennes opérations.



\---



\### 3.4. Améliorer la gestion du parc automobile



Permettre à ADIKOM de connaître à tout moment la situation de chaque véhicule.



Le système doit notamment permettre d'identifier :



\- les véhicules disponibles ;

\- les véhicules réservés ;

\- les véhicules actuellement loués ;

\- les véhicules en maintenance ;

\- les véhicules immobilisés.



Chaque véhicule doit disposer d'un historique permettant de suivre son exploitation et son évolution.



\---



\### 3.5. Améliorer la gestion de la maintenance



Centraliser les informations relatives aux interventions effectuées sur les véhicules.



Le système doit permettre de suivre :



\- les pannes ;

\- les interventions ;

\- les réparations ;

\- les coûts ;

\- les pièces justificatives ;

\- les dates ;

\- les prochaines échéances ;

\- l'historique du véhicule.



L'objectif est également de permettre une meilleure anticipation des opérations de maintenance.



\---



\### 3.6. Assurer la traçabilité des coûts imputables aux fournisseurs



Lorsqu'un véhicule fourni par un fournisseur nécessite une réparation dont le coût doit être imputé à ce fournisseur, le système doit permettre de gérer cette opération de manière structurée.



Le système doit pouvoir relier :



\*\*Fournisseur → Véhicule → Incident → Maintenance → Dépense → Imputation → Facture fournisseur → Solde\*\*



L'objectif est de garantir une traçabilité complète et d'éviter toute modification financière non justifiée.



\---



\## 4. Objectifs financiers



\### 4.1. Améliorer le suivi de la facturation



Permettre de suivre les factures clients et fournisseurs depuis leur création jusqu'à leur règlement.



Le système doit permettre de connaître :



\- les factures créées ;

\- les factures réglées ;

\- les factures partiellement réglées ;

\- les factures en attente ;

\- les factures en retard ;

\- les montants restant à payer.



\---



\### 4.2. Améliorer le suivi des paiements



Centraliser les paiements et permettre leur rattachement aux opérations concernées.



Un paiement doit pouvoir être relié, selon le cas, à :



\- une facture ;

\- un client ;

\- un fournisseur ;

\- une location ;

\- une dépense ;

\- un compte bancaire ;

\- une caisse.



\---



\### 4.3. Améliorer la visibilité sur la trésorerie



Permettre à ADIKOM de suivre ses banques et caisses et de connaître les mouvements financiers enregistrés.



Le système doit permettre de suivre notamment :



\- les entrées ;

\- les sorties ;

\- les virements internes ;

\- les soldes ;

\- les écritures ;

\- les justificatifs.



\---



\### 4.4. Améliorer le suivi de la rentabilité



À terme, ADIKOM PILOT doit permettre d'analyser la rentabilité des activités et notamment celle du parc automobile.



Le système doit progressivement permettre de rapprocher :



\*\*Revenus → Coûts → Dépenses → Résultat estimé\*\*



Pour un véhicule, cela pourra notamment permettre d'étudier :



\- les revenus générés ;

\- les dépenses de maintenance ;

\- les autres dépenses ;

\- les coûts d'exploitation ;

\- l'utilisation du véhicule ;

\- la rentabilité estimée.



\---



\## 5. Objectifs liés aux utilisateurs



\### 5.1. Donner à chaque utilisateur les bons accès



Chaque utilisateur doit disposer uniquement des accès nécessaires à l'exercice de ses responsabilités.



Le système doit permettre de gérer les droits à travers :



\*\*Utilisateurs → Groupes → Permissions\*\*



\---



\### 5.2. Protéger les fonctions sensibles



Les fonctions sensibles doivent être accessibles uniquement aux utilisateurs autorisés.



Cela concerne notamment :



\- gestion des utilisateurs ;

\- gestion des permissions ;

\- paramètres sensibles ;

\- opérations financières ;

\- suppression de données ;

\- validation d'opérations ;

\- modifications importantes.



Le Super Admin dispose des droits complets et assure l'administration des accès.



\---



\### 5.3. Faciliter le travail quotidien



Le logiciel doit réduire les manipulations inutiles et permettre aux utilisateurs de trouver rapidement les informations dont ils ont besoin.



L'interface doit privilégier :



\- simplicité ;

\- clarté ;

\- rapidité ;

\- cohérence ;

\- recherche ;

\- actions directes ;

\- informations contextuelles.



\---



\## 6. Objectifs de pilotage



ADIKOM PILOT doit permettre de transformer les données opérationnelles en informations utiles à la décision.



Le système doit notamment permettre d'identifier :



\- les situations urgentes ;

\- les échéances proches ;

\- les retards ;

\- les anomalies ;

\- les opérations importantes ;

\- les tendances ;

\- les performances.



Le tableau de bord doit ainsi servir de véritable outil de pilotage.



\---



\## 7. Objectifs de communication interne



Le système doit faciliter la circulation des informations importantes au sein de l'entreprise.



Le Centre de Notifications doit permettre de signaler les événements nécessitant une attention particulière.



Le module Projets \& Planification doit permettre de structurer :



\- les tâches ;

\- les échéances ;

\- les réunions ;

\- les actions ;

\- les décisions ;

\- les responsabilités.



L'objectif est de limiter les oublis et de donner une meilleure visibilité sur le travail en cours.



\---



\## 8. Objectifs de traçabilité et de contrôle



ADIKOM PILOT doit permettre de conserver un historique des opérations importantes.



L'objectif est de pouvoir répondre à des questions telles que :



\- Qui a créé cette réservation ?

\- Qui a modifié le tarif ?

\- Qui a enregistré ce paiement ?

\- Qui a validé cette opération ?

\- Quand cette modification a-t-elle été effectuée ?

\- Pourquoi cette dépense a-t-elle été imputée au fournisseur ?

\- Quel montant a été déduit ?

\- Quel était le montant initial ?



Cette traçabilité doit renforcer le contrôle interne et la fiabilité des informations.



\---



\## 9. Objectifs d'évolutivité



Le système doit pouvoir accompagner la croissance d'ADIKOM.



La première version doit être centrée sur la gestion de location, mais son architecture doit permettre l'ajout progressif de nouveaux modules.



L'objectif est de pouvoir développer progressivement :



\- gestion de location ;

\- banques et caisses ;

\- facturation et paiements ;

\- projets et planification ;

\- gestion commerciale ;

\- autres fonctions internes nécessaires.



L'ajout de nouveaux modules ne doit pas nécessiter de reconstruire entièrement le système.



\---



\## 10. Objectifs de sécurité



ADIKOM PILOT doit protéger les informations internes de l'entreprise.



Les objectifs comprennent notamment :



\- authentification sécurisée ;

\- contrôle des permissions ;

\- séparation des responsabilités ;

\- protection des données sensibles ;

\- traçabilité des actions ;

\- gestion sécurisée des sessions ;

\- protection des secrets techniques ;

\- limitation des accès selon les rôles.



Aucune donnée sensible ou information d'authentification ne doit être exposée dans le code source, les fichiers de documentation ou les dépôts publics.



\---

Le système doit être :



\- responsive ;

\- performant ;

\- maintenable ;

\- évolutif ;

\## 13. Critère principal de réussite



ADIKOM PILOT sera considéré comme réellement utile lorsque l'équipe pourra gérer une opération de location de véhicule de manière cohérente depuis sa création jusqu'à sa clôture.



Le système doit permettre de suivre le processus :



\*\*Client → Tarif → Réservation → Véhicule → Contrat → Départ → Location → Retour → Contrôle → Éventuelle maintenance → Facturation → Paiement → Clôture\*\*



Et, lorsque cela est nécessaire :



\*\*Véhicule fournisseur → Maintenance → Dépense → Imputation fournisseur → Déduction → Solde fournisseur\*\*



\---



\## 14. Principe final



Chaque fonctionnalité développée doit contribuer à au moins un des objectifs suivants :



1\. mieux organiser ;

2\. mieux exécuter ;

3\. mieux contrôler ;

4\. mieux suivre ;

5\. mieux mesurer ;

6\. mieux décider.



Si une fonctionnalité ne répond à aucun de ces objectifs, sa pertinence doit être questionnée avant son développement.



\*\*ADIKOM PILOT doit rester un outil au service de l'organisation et du pilotage d'ADIKOM, et non devenir une source supplémentaire de complexité.\*\*
